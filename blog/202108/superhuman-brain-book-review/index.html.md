## 一、輸入

讓你擁有高效學習的方法

### 限定做筆記的次數

大部分的人都有看書做筆記的習慣，但人的記憶力有限；如果筆記做了太多，反而阻礙了大腦對知識的吸收效率。

但如果在看一本書時只允許你出手五次，那這個筆記的內容就會是真正的精華。

### 你是會用框架，還是了解框架

為了讓產品可以更快發表且擁有一定的穩定度，「框架」應運而生；但能夠把框架用的好跟能力真的好並非絕對相關。

框架用得好只是因為別人已經幫你把路給鋪平了，如果你不了解這條路是如何鋪平的，在遇到問題時很容易束手無策；失敗的記憶比成功更深刻，錯誤後才能理解為何要這樣使用。

### 記憶的關聯性

去學你真正會用到的技能，如果這門技能與你的工作、興趣沒有關連性，就算當下學會了也會在很短的時間忘記。

如果想讓這些技能有延展性，就要學以致用，以筆者個人舉例：

2019 年幫朋友撰寫了一個可以幫助他工作的爬蟲程式（程式的技能）

2020 以這個爬蟲程式為基礎參加了 iT 邦幫忙鐵人賽（程式＆寫作技能）

2021 以 iT 邦幫忙比賽系列文為基礎出書（同時提升程式＆寫作技能）

### 聽演講、開會

如果演講的內容毫無意義就閉目養神吧、如果開會的內容與自己幾乎無關就自己找事做吧；不要把精神放在對自己沒有幫助的事情上。

如果這場演講、開會內容很重要，在過程中就要記錄關鍵訊息，結束後立刻總結把細節補齊，千萬不要覺得開會太累想先休息一下再做紀錄，紀錄的動作隔了 30 分鐘甚至 1 個小時再做會發現事倍功半。

### 花錢買知識

靠自己摸索一門不熟悉的技術，在開始會遇到很多的撞牆期；在生活步調極其迅速的社會，這些碰壁足以讓你放棄這門技術，但如果放棄了這門技術就代表前面所花的時間都白費了，這些時間也是要算進成本裡面的。

如果這個技術能給你帶來幫助，我認為購買課程是一個很有價值的投資。

### 刻意練習

大部分的工程師在完成功能後就會把 Issue ticket 給關掉；在寫完程式後會做 Code Refactor 的人真的很少，但這這個動作決定了非常多的細節。

如果可能，我建議在 Code Refacor 時除了優化程式外，也要把功能的關聯性、開發時間、實作思路紀錄在 Issue ticket 上面；這樣不但能提高你對程式的掌握度，還能在日後遇到變更時快速回憶。

## 二、輸出

寫作是一個很棒的輸出形式

### 換個解決方案

有時遇到問題時不是沒有想法，而是有太多想法，電腦打字的速度飛快，但是頭腦轉速更快，最後就打結了。此時可以改用紙本手寫，換一個方式來做輸出，反而會更有條理。

### 寫作的內容

正向思維：「你想要表達什麼？」將自己想要表達的想法先以大綱呈現。

逆向思維：「讀者會想要知道甚麼？」從讀者的角度去整理文章的內容。

建議在寫作前將大綱擬好，然後統整，最後安排出場順序，這樣的做法可以用上帝視角來觀察是否有缺漏的部分。

### 寫作的方式

你可以回想一下，是不是常常跟同事用打字討論到一半就改用語音或是視訊了？

這是因為同一時間打字能夠輸出的訊息量遠低於語音與視訊；拜科技所賜，我們可以改成使用語音的方式來寫作，以防你打字打到不耐煩崩潰。

### 明確的受眾

如果文章沒有明確的受眾，那寫作的思路非常容易打結，因為使用的口吻、知識的深度都會不同，如果想要討好所有人，最後往往一個都討好不了。

### 利用適當的放鬆與罪惡感提升自己做事效率

違抗自己內心的想法會導致做事效率降低，回想學生時期如果是被父母逼著唸書，你學習的速度絕對不快；但如果說念完這本書就能夠出去玩，你讀書的意願就會上升。

長大後我們常常會被逼著做一些很重要的事情但就是提不起勁，這時可以先做有罪惡感的事（EX：玩遊戲、看漫畫），當你感受到不能再混下去的時候效率往往是最高的。

### 記錄自己擔心的東西

如果你是用逆向思維來撰寫文章，有時會擔心自己是否夠資格寫這篇文章；此時可以把你擔心的點一一記錄下來，你所擔心的東西往往也是其他人需要的東西，這些內容最後還可以成為你寫作的大綱。

## 三、持續成長

成長要符合自己的慾望

### 養成帥氣的習慣

會變強是因為喜歡做某件事情，並且覺得持續做這件情很帥氣，有些人喜歡健身，因為健身後得到的好身材很帥氣，有些人喜歡寫作，是因為發表文章這件事很帥氣。

他們之所以能夠堅持不是因為意志力強過你我，而是這些事情對他們而言，因為反覆的訓練而變得很簡單。

### 上癮

任何偉大的成就，背後就是一群對這個領域上癮的人，先是普通人，上癮之後才成為專家。

### 訂下絕對不要去做某件事情的時間

我們不確定做哪些事情是正確的，但至少可以藉由經驗訂下絕對不要去做的事情。

假設公司準備要把某個版本部署出去，建議不要選擇吃飯前[11:30~12:00]跟下班前[17:30~]的時間點，這兩個時間點很容易因為想要趕快吃飯、下班而造成低級錯誤，而且錯誤造成後續處理更加焦躁，甚至延伸更多錯誤發生。

### 有些幸運是實力

在學習上你會發現明明起跑點一樣，為什麼有些人就是跌跌撞撞，而有些人一帆風順，其實很有可能那些看起來一帆風順的人在過去已經踩過各種跌跌撞撞的坑了；不是他現在都沒遇到坑，而是他知道怎麼避開這些坑。

### 專注尋找幸運而非不幸

**狀況題**：今天下雨，在半個小時後你跟朋友有約，你會選擇叫計程車、坐公車還是搭捷運抵達目的地？

如果風和日麗，坐公車與捷運是沒問題的，但如果是下雨，你就要考量到自己如果選擇坐公車會不會遇到堵車、選擇搭捷運會不會要撐雨傘走一段路，儘管計程車會花比較多錢，但他可以讓你在抵達目的地前有好心情，避免掉那些可能會發生的倒楣事。

### 不要賭博

如果遇到了運氣相關，但能夠用錢解決的事情，就用錢去解決吧。

### 學習相關領域

與程式相關的領域是甚麼？我想絕大多數人都不會聯想到「建築」這個行業；程式只有 20、30 年的歷史，但建築是從人類有文明以來就不斷研究的東西，程式中的 Design pattern 最早也是來自於建築，裡面很多設計的邏輯都可能讓你觸類旁通。

### 透過面試變強

不是面試越多就會越強，而是在每次面試後都有總結的人才會變強。去思考自己適不適合這類型的公司、裡面問到的問題哪些是我不會的、有沒有吸收到自己從未有過的思路、哪些地方還可以改進、這個面試官有哪些優缺點；有留下紀錄才能夠對比與思考，進而了解未來學習的方向。

## 四、總結

相比於其他浪費時間的雞湯文，這本書真的讓我學習到很多能「實際操作」的方法。

學習新方法很簡單，但真正能活用到生活中才能給你的人生帶來實質性的幫助，文章僅節錄部分書籍內容，有興趣的讀者可以先參考作者在 [GitHub](https://github.com/xdite/memory-hack) 上發表的文章。
