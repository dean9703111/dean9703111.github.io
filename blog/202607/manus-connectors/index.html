沒有連接器，人類就是搬運工

在進入實戰前，我先帶大家回想，過去我們是怎麼跟 AI 互動的？

複製來複製去，人類比 AI 更像機器人

比如你想讓 AI 幫忙回一封信，是不是先把信件內容複製起來，貼給 AI 請它寫草稿？

但這個流程存在幾個個問題：

  1. 如果這是一串來回對話的信件，AI 並不會知道你們過去聊了些什麼，因為它只拿到最後一封的資訊。
  2. 在這樣的狀態下，AI 可能會因為資訊不足詢問你更多細節；假如你沒有認真回覆，當 AI 的答案不如預期時，問題可能出在你給的資訊不夠。
  3. 另外，你在得到 AI 答案後還要切到信箱視窗貼上回覆。

在這段操作中，你在做的事情只是搬運資訊。

資訊太多不知道如何找

這邊再舉一個案例，有些公司會使用 Notion 作為專案管理工具。

但隨著專案的時間拉長，裡面的會議記錄、需求規格會越來越複雜，而且一個人手上可能同時負責多個專案。

再加上公司可能會有人員的流動，因此幾個月後當主管或客戶問起專案的某個問題時。

你可能早就忘記過去的決策，甚至是第一次接觸這個專案的同事，連搜尋的關鍵字都不知道怎麼下，所以要花很多時間在考古上。

建立連接器，讓 AI 接上你的日常工具

如果前面這些痛點讓你感到共鳴，我們在 Manus 建立連接器後，都可以迎刃而解。

人類的價值應該在於決策，而不是這些瑣碎、重複的操作。

點擊左側頭像，選擇「設定」，在側邊欄可以看到「連接器」的分頁。

點擊「瀏覽連接器」就能看到 Manus 已經幫我們預設許多可以直接使用的工具。

我們只要開啟對應工具的權限，Manus 就可以透過 API 進行操作，而 API 你可以理解成工具開給程式呼叫的服務窗口。

那今天我會以 Gmail、Google Calendar、Notion 這些日常工具做示範。

以前寫信要開 Gmail、建立行程要開 Google Calendar、查資料要翻 Notion，不同工具切換很耗費精神；但設定好連接器後，這些任務就能在 Manus 集中管理。

這邊也補充一個小知識，這類工具連結的背後，有一個通用的技術標準叫做 MCP。你可以把它想像成 AI 世界的 USB 窗口，只要符合這個標準的工具，都可以接上 AI。

另外 Manus 也支援自訂 API 與 MCP，如果你想連接的工具沒出現在列表上，也可以自行新增。

① 連接 Gmail，讓 AI 整理信件、建立標籤

這邊先從大家日常會使用的信箱開始，相信很多人的信箱都是爆炸的狀態，裡面充滿垃圾信、電子報、行銷廣告、過期會議邀請…

而這可能會導致真正重要的信被埋在下面。

但刪除信件很麻煩，我也懶得將廣告信一一封鎖；既然你也有這樣的想法，那我們就把這個任務交給 AI 吧！

建立 Gmail 連接

這邊我們把畫面切到 Manus，回到剛才介紹過的連接器頁面；在瀏覽連接器的部分貼上「Gmail」。

打開點擊連結後，選擇要授權的信箱，就會跳出 Google 的詢問頁面。

完成授權後，就會再跳轉回 Manus 畫面，看到信箱出現在上面就代表成功嚕～

連結完成後，點擊「試試看」開一個新的對話，你會看到官方一開始就有提供一個提示詞的模板讓你了解如何使用。

可以點擊「發送」檢查功能是否正常，並得到初步說明。

提示詞解析：分類規則與保險機制

確認功能符合預期後，可以貼上這段提示詞讓 AI 協助分類信件：

幫我整理 Gmail 最近 30 天內未標籤的信件（最多 [50] 封），步驟如下：

## 第一步：分類打標籤
閱讀每封信的寄件人、主旨（不需閱讀內容），依下列規則加上標籤：
- 🔴 重要：來自真人（非系統信）、需要回覆或行動、來自我的聯絡人
- 📁 封存：通知類、收據、訂單確認、已讀但無需回覆
- 🗑️ 刪除候選：促銷、電子報、自動發送的廣告信、過期的會議邀請、寄件人是 no-reply
有疑慮時，優先歸入「封存」而非「刪除候選」。
## 第二步：整理廣告寄件者清單
找出符合以下任一條件的寄件者：
- 過去 30 天內寄超過 2 封促銷/電子報
- 主旨含有「優惠、折扣、限時、unsubscribe、newsletter」等關鍵字
- 寄件地址為 no-reply@ 或 marketing@ 開頭
輸出格式：
| 寄件者名稱 | Email 地址 | 封數 | 建議動作（取消訂閱／封鎖） |
## ⚠️ 執行前確認
以上兩步驟完成後，先給我清單讓我確認，
我明確說「確認執行」後，才進行標籤套用動作。

送出後，我先跟大家解析這段提示詞的設計重點：

① 首先是範圍限制，我要求他搜尋 30 天內未標籤的信件，並且最多 50 封；我們先確認小範圍的執行符合預期後再擴大，避免浪費積分。

② 然後是分類規則，我把「重要、封存、刪除候選」各自的判斷條件講得很明白；而且還加了一句「有疑慮時優先封存」，因為封存的信在「所有郵件」還找得回來，刪除三十天後就永久消失了。

③ 另外要求用表格輸出廣告寄件者清單，有設定好欄位才方便我們快速判斷。

④ 最後，也是最重要的，我要求他「執行前先跟我確認」，這就是我前面說的保險機制。

實際執行與結果驗證

指令送出後，你可以看到 Manus 開始讀取信件的寄件人與主旨。稍等一段時間，分類清單就整理出來了，哪些重要、哪些可以封存、哪些是刪除候選，一目了然。

確認沒問題後，跟他說「確認執行」，Manus 就會開始對信件進行分類標籤；執行完畢後，我們回到 Gmail，這邊可以看到標籤真的建立起來了，信件也都分類完成。

這邊再提醒一下大家，刪除信件、取消訂閱這類高風險操作，我建議在標籤建好後由人類來做最後判斷，因為有些 no-reply 的信件可能是繳費通知

另外建議大家先小範圍測試，比如先 50 封，沒問題後再擴大範圍、調整判斷規則。

② 查詢 Gmail，彙整多封信件的討論脈絡

接下來分享一個我自己常用的功能。

與同事、客戶的信件，通常有多段來回、細節持續調整，而且每一段可能都有重要資訊；更麻煩的是，討論可能不在同一封信，而是散落成好幾封。

像我自己有些合作案，從接洽到結案可能有好幾個月，中間還可能會更換主題、換對接的窗口。

要回憶當初談了什麼條件、改過哪些內容，光翻信就要花半天。

但在我們建立連接器後，現在只要給予關鍵字，Manus 就會搜尋相關的信件，幫你把整個合作的時間軸、關鍵決策、待辦事項整理出來。

幫我整理 Gmail 信箱中 [黑寶科技] 合作的過程，列出：
1. 關鍵決策和協議
2. 聯絡人和負責人
3. 財務或合約相關信息

稍等一段時間，過去自己翻半天可能還一頭霧水的東西，現在馬上就有一份完整的脈絡。

這邊除了簡短的摘要外，Manus 針對細節也有對應的報告，幫助我們快速掌握所需資訊。

這邊再跟大家做個補充，Manus 連接器除了支援 Gmail 外，Outlook 也有支援的喔！

那如果你們公司用的是自建信箱，在不涉及機密的前提下，可以考慮用密件副本寄到 Gmail，讓 AI 可以去做一個讀取。

③ 搭配 Google Calendar，把混亂討論建立成事件

接下來跟大家分享連接器的綜合應用，這邊我就以「建立會議行程」作為範例。

回想一下，過去開會前，我們需要做哪些事前準備？

像是彙整會議資料、確認與會者可以參與的時間、確認哪些人需要出席，在發出會議前還要整理一份議程讓大家知道這個會議的目的。

這是一件非常瑣碎的任務，因為會議的時間、地點、文件，可能散落在信箱的討論串中；手動彙整不但花時間，還容易遺漏細節、參與人員。

既然如此，不如把彙整資訊、建立行程的任務交給 AI 來幫我們處理。

一樣到連接器的頁面，這邊先把 Google Calendar 加入連接器，授權的模式跟前面的 Gmail 都是一樣的。

從 Gmail 信件建立行程

這邊連接完成後，貼上這段提示詞：

從 Gmail 找出[Q3 新品活動｜上線滿月成效初步整理]信件，並在 Google Calendar 建立行程：
- 抓出最後會議的日期、時間、地點
- 在行程說明裡附上議程重點
- 取出信件討論人員，設定為 attendees
- 如果時間和我現有行程衝突，先提醒我
建立行程前，請先提供草稿讓我過目

這段提示詞做了幾件事：從 Gmail 找信、抓時間地點、整理議程、加入與會人、檢查是否與既有行程衝突。

而且最後一樣有保險機制：「建立前先給我草稿過目。」

稍等一段時間，Manus 就從信件討論串抓出最後拍板的結論，並把議程整理出來；確認沒問題後，點擊接受行程就直接建立到行事曆上了。

接下來我們把視角切到 Google Calendar，可以確認時間、地點、與會人、議程都新增如預期。

這邊特別提醒一下大家，給予授權後，AI 是真的會建立行程，而且會發送會議邀請給與會人，因此執行前請務必確認內容。

④ 授權 Notion，把知識庫變成可以問答的 AI

最後一個案例是 Notion，這邊先簡單介紹一下，Notion 是一款整合筆記、知識庫、Wiki 的工具。

有些團隊用它來記錄產品規格、常見問答、會議記錄的資訊，或作為專案管理的工具，像我自己就把它當成個人筆記的知識庫。

但當資訊量龐大到一定程度時，你可能還是會難以找到所需資訊。

建立連結與範例知識庫

但幸好現在有了 AI，我們把視角切換到 Manus。

連接 Notion 時，需要允許 Manus 來呼叫 Notion MCP，然後點擊 Continue。

把 Notion 加入連接器後，你不用再自己慢慢找，直接「問」就能找到答案，還能標明出處，等於給知識庫裝上了搜尋引擎與摘要功能。

另外如果你還沒有 Notion 帳號，用 Gmail 註冊免費版就可以使用了。

我也準備了一個範例知識庫：

https://kaput-lord-cf7.notion.site/e4f7378f09a346ed8cee5c552b2754d0

打開範例頁面後，點右上角的「建立副本」，就會存進你自己的 Notion。

限定範圍、要求出處

連結完成後，貼上這段提示詞：

去 Notion 工作區的 [AI 知識庫] 幫我尋找「Manus 技巧」的頁面
① 回答我的問題，並附上你引用的頁面標題與連結
② 如果範圍內找不到答案，直接說「範圍內查無資料」，不要自己編

這段提示詞的重點有兩個。

  1. 限定搜尋範圍，指定某個頁面或資料庫，這樣 AI 只會在這個範圍內找，不會拿網路上的資料亂湊
  2. 要求附上出處，並要求它找不到就要誠實說「查無資料」。

稍等一段時間，你可以看到 AI 找到了對應的頁面，回答了問題，還附上引用的頁面標題與連結。

這邊我點擊一下連結，來驗證 AI 確實有找到對應資訊。

詢問範圍外的問題

這邊我也做一個測試，故意問 AI 一個範圍外的問題，看他是否會唬爛

請在 Notion 的 [AI 知識庫] 幫我尋找「工程師林鼎淵 Dean Lin 經歷」

你可以看到他誠實回答「範圍內查無資料」，而不是自己瞎編一個答案

這個「要求出處、禁止瞎編」的技巧，是減少 AI 幻覺最實用的方法，這個技巧我在後續分享 Manus 專案功能時也會使用。

⑤ 自訂 API，連接不在列表的工具

前面示範的案例，都是用 Manus 連接器預設就有的應用程式。

但如果你想用的工具沒有出現在列表上呢？

其實我們也可以自己新增，這邊我用「自訂 API」示範給大家看。

我知道看這個頻道的朋友，有許多人是工程師，而大家做專案版本控制的工具可能是 GitLab。

但 GitLab 並沒有出現在預設的連接器中，如果你希望把 GitLab 專案的存取權，允許讓 Manus 去做存取，就可以透過自訂 API 來達成。

取得 GitLab 的 Access Token

首先，我們要到 GitLab，並在這邊取得 Access Token，它就像一把有使用範圍的鑰匙。

進入 GitLab 畫面後，點擊「Edit profile」，選擇側邊欄的「Access」底下的「Personal access tokens」的設定頁面。

點擊「Generate token」時，它有分成兩種，這邊我選擇「Legacy token」來做 Demo。

  • Token name: manus
  • Select scopes: 勾選 read_user、read_repository、read_api 這些讀取的權限

Token 生成後，畫面有提醒你他只會出現一次，所以要好好保存，這邊我把 Token 複製起來。

在 Manus 自訂 API

然後回到 Manus，在自訂 API 的畫面中

  • 名稱: GitLab
  • 備註: 可以使用密鑰的 Token 來讀取 https://gitlab.com 的 Repo 資訊
  • 密鑰名稱: GITLAB_TOKEN
  • 密鑰數值: 把剛才複製的 Token 貼上去就好

這邊要特別提醒大家，前面設定 Token 的權限，就是 Manus 操作 Gitlab 的權限。

所以建議大家先用 Read 讀取權限來驗證是否符合預期；確認沒有問題後，再逐步擴增其他權限。

另外 Token 是隱私資訊，千萬不要外洩

儲存後，我們開啟一個新的對話窗，輸入指令：

請幫我讀取 GitLab 底下的個人專案，列出名稱

稍等一下，就可以看到 Manus 成功讀取到我們的專案嚕～

在了解設定的方式後，未來大家就可以根據自己的需求，來自定連接器了。

結語：把瑣碎交給 AI，把決策留給自己

最後我們來回顧一下今天的影片：

  1. 一開始我們建立了與 Gmail 的連結，讓 AI 有能力建立標籤、彙整信件脈絡。
  2. 然後再延伸到 Google Calendar，這邊我們以信件討論示範，讓 AI 將散落的資訊整理成明確的議程並幫我們建立行程、發會議通知。
  3. 接著示範如何連接 Notion，讓知識庫變成搜尋引擎。
  4. 最後補充自訂 API 的流程，就算工具不在預設列表裡，只要它有 API，一樣可以接上來。

設定好連接器後，過去要在不同工具間切換、複製貼上的任務，現在都能在 Manus 上操作。

這邊提醒一下大家，雖然連接器很方便，但因為 AI 真的可以幫你做事；如果想降低誤操作的風險，可以在提示詞最後補上「執行前先給我確認」。

別忘記，目前 AI 還無法替人類背鍋，你需要為自己的決策負責。

教會 AI 一次，它永遠記得，還能分享給他人共用，讓大家站在更高的起點。
