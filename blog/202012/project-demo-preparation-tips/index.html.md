你費盡千辛萬苦與夥伴完成了這份專案，明天就是展示你們成果的時刻！但如果你在 Demo 前忽略了這些細節不但會影響發表的成效，如果**發生嚴重意外甚至會影響到你的考績與年終**；為了確保每次 Demo 的水平，這篇文章會列出筆者過往 Demo 時遇到的問題及解決方案。

這篇文章會分成五個部分來說明每次 Demo 前需要注意的細節

## 一、保證現場 Demo 效果，不打沒把握的仗

穩定比表現的突出更重要

### ➤ Demo 前要盡可能的測試

如果 Demo 現場產品出包你講的內容再好都無力回天了。

### ➤ 同事間的預演

自己組內要先演練過，互相提醒要調整的地方，這個動作能讓其他同事知道你 Demo 時要講的內容，如果很不幸當天發生了什麼變故還能出來擋一下。

### ➤ 只用一台電腦做 Demo

如果需要輪流上台請將資料都存到一台電腦上面，因為 Demo 過程換電腦不但浪費時間並且會打亂會議的流暢程度，我甚至看過換電腦後有色偏、斷訊、閃爍的問題。

### ➤ 不要讓頹廢的外型把你的專業扣分

第一印象很重要！上台請穿著得體，並且不要散發異味！

## 二、邀請“對”的人，不是”多“的人

事半功倍 VS 事倍功半

### ➤ 重要的長官一定要出席

如果最關鍵的 Key man 如果無法出席，你這次的 Demo 可以說有一半以上的意義都沒有了；因為就算有代理人出席，他也只能做到轉述，實際效果就跟你分享電影情節給朋友差不多。

所以 Demo 的日期時間會以 Key man 能到現場的時間為主。

### ➤ 不要邀請一堆無關的閒雜人等

很多會議為了要做排場給長官看就邀請了一堆跟專案無關的人參與會議，這樣的做法只會造成台下一堆人在滑手機

## 三、選擇合適的會議室

如果可以絕對要提前場勘，不然很容易死得不明不白

### ➤ 會議室的座位只能多不能少

要確保座位數量足夠，建議預留20%的空位給臨時參與的人

### ➤ 確認會議室適合觀看 Demo 的座位

因為大部分的會議室都是平面的，所以一定會有一些角落的位置不適合觀看，所以你要確保會議的 Key man 坐在觀看 Demo 的最佳角度（建議有人負責引導長官座位或是有座位名牌）

### ➤ 測試現場投影機並確認規格

一定要用當天 Demo 的電腦測試看看是否可以順利投影，以及投影上去是否有模糊、字體大小、色偏…等問題。

同時記得確認投影機轉接頭是 HDMI 還是 RS232，現場是否有提供轉接頭還是要自己準備。

### ➤ 每個要上台 Demo 的人在講台試講一小段

因為每個人的說話聲音大小不同，同一個場地有人需要麥克風有人不需要，所以可以藉由這個試講來確認，同時也能讓上台的人熟悉講台以及知道自己要站的位置。

### ➤ 預定會議室

除了提早訂會議外，同時要注意：

- 除了 Demo 的時間外，前後都至少要留 1 小時緩衝（再次確認場地環境、會後交流）
- 這個會議室是否有上一批人使用過，是否需要預留時間進行場復

### ➤ 確認網路環境

- 是否有穩定的 wifi 或是網路線連接口，建議拿當天會用的電腦直接測速會比較安全（有些公司的網路只能連接內網，這塊也需要注意）
- 使用自己的手機熱點網速是否穩定

## 四、在 Demo 過程中要注意的事項

這塊 PM 需要適時的去協助

### ➤ 記得關閉社群軟體及網頁

如果在 Demo 過程中跳出奇怪的訊息是非常尷尬的，而且訊息跳出來的聲音也很吵。

### ➤ 現場燈光控制

在 Demo 過程你要知道會議室燈光怎麼調整是讓觀眾最舒服的，因為全暗的環境會眼睛不太舒服(ex:只關閉前面幾排)

同時在問答階段及切換講者的階段建議燈光是全開的，這樣講者與觀眾的互動比較友善。

### ➤ 讓每個 Demo 人員的時間都在掌控之內

有些與會者會不停打斷 Demo 的過程，不停拋出問題（通常會這樣做都是高級長官）導致會議時辰脫離掌控，這時你就需要視情況做回應，或是引導他們在 Demo 結束後再發問（其實他們的發問很多時候只是 Demo 還沒講到那個部分而已）。

### ➤ 記得帶筆記本上台

通常在 Demo 過程中都是使用鏡像螢幕，如果中間遇到發問你不可能使用電腦來記錄問題，如果你拿出手機來紀錄有時會引起老一輩的不悅；這時筆記本就是一個非常好的工具。

## 五、遠端 Demo 前要做的確認清單

如果要向國外的客戶做 Demo，又或是因為疫情影響需要在家 Demo

### ➤ 確認雙方畫面穩定性和對話即時性

因為是遠端所以非常吃雙方的網路速度，有時會有畫面及聲音的延遲造成溝通上的問題，甚至會因為其中一方的訊號比較差導致畫質下降。

### ➤ 確認雙方的音量大小以及雜訊

- 先讓每位主講者先簡單自我介紹確認的聲音大小，避免有些人超大聲有些人超小聲。
- **遠端開會時除了主講者外其他人都要靜音**，不然很容易會有雜訊
- 建議購買專用的麥克風收音，這樣可以大幅降低周遭環境音（ex：咖啡廳背景音樂、小孩哭鬧聲、鄰居吵架聲…）

### ➤ 使用 wifi 熱點時注意不要流量互搶

在家中通常是連接 wifi ，但如果很多人共用這個 wifi 可能會導致視訊品質不佳。

### ➤ Demo 需要高流量的網站

部分網站在操作時會消耗掉大量的流量，這很有可能造成你畫面的卡頓，建議你可以先找朋友測試看看，以保證當天勤務萬全。

Demo 過程發生的意外對台下的觀眾而言是一種必然，因為他們只會聽一次而已；請不要讓這些可以控管的風險把你所努力的成果給毀掉，每次 Demo 前都按照這份清單檢核一次吧！
