- 主題：團隊合作
- 標籤：溝通、工程師溝通、了解工程師、工程師在想什麼、工程師必讀
- 摘要：今天推薦的系列文，可以說是我近年來看過舉例最真實、系統最完整、描述最白話的好，我相信無論你是工程師、專案經理、產品經理都能從中獲取非常寶貴的經驗及知識。

撰寫技術文章常常需要尋找資料佐證自己的想法是正確的，而找參考資料的同時也會發現很多同質性高的文章，每當遇到這種狀況就讓我不禁思考自己寫的這篇文章有存在的意義嗎？

也許很多人文章寫到一半都曾冒出過這個念頭，就像是我今天原本打算要寫一篇跟工程師溝通有關的文章，結果沒想到 Google 出來的第一篇文章才看不到三篇就讓我把寫好的草稿默默地刪除了…

今天推薦的系列文，可以說是我近年來看過舉例最真實、系統最完整、描述最白話的好文，我相信無論你是工程師、專案經理、產品經理都能從中獲取非常寶貴的經驗及知識。

雖然文章標題是`菜鳥工程師必修的30堂溝通課`，但裡面很多談到的東西都是資深工程師甚至資深PM都沒有做到的：

- **菜鳥工程師**：能從中了解在初入職場時該如何溝通，讓自己儘速成為公司戰力與前輩們合作愉快
- **資深工程師**：可以來審視自己有沒有養成一些不好的習慣，造成 PM 以及同事間合作上的困難
- PM：這系列文簡直是職涯上的救贖，你可以搞懂工程師的大腦到底在想什麼東西

在文章中也解答了許多人的共同疑惑，如：

- 為什麼工程師沒辦法準確的估計作業時間？
- 身為工程師如何讓非專業領域的人理解自己表達的內容？
- 工作與興趣是有結合的可能性嗎？
- 如何提高效率讓自己提早下班？
- 怎麼做到職場上的情緒管理？

如果你已經看膩了職場雞湯文，這個系列文章的思路絕對讓你耳目一新，當然我的描述不及文章之萬一，[趕緊手刀點下去拜讀吧！！！](https://ithelp.ithome.com.tw/users/20040221/ironman/2236?sc=iThelpR)
